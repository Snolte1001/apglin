# Audi 8W1 919 616 B: Tastenfeld 1–8 am LIN-Bus

Tastenfeld mit den Ziffern 1–8 und Tastenbeleuchtung. Mechanisch gibt es
nur **einen Schalter für das ganze Feld**: Egal welche Ziffer man drückt,
das ganze Feld bewegt sich nach unten. Welche Ziffer gemeint ist, erkennt
das Tastenfeld kapazitiv an der Fingerposition.

Belegung am 30.10.2026 an einem Gerät gemessen: APGDT001 (Firmware
`0x2304`) als Master mit Master-Pull-up, VBAT, Tastenfeld als einziger
Slave. Alle Antwort-IDs wurden zyklisch abgefragt (0x20 etwa alle 55 ms,
die übrigen alle ~280 ms; 23 316 Frames, ohne Fehler außer den
Weck-Headern), dabei wurde jede Ziffer einzeln bedient.

| | |
|---|---|
| Baudrate | 19200 Bd |
| Prüfsumme | enhanced (alle Frames) |
| Slave-Frames | `0x20` (2 Byte), `0x2A`–`0x2E` (je 8 Byte); auf andere IDs `0x00`–`0x3B` keine Antwort |

## Tasten: `0x2E` (entprellt)

| Byte | Bedeutung |
|---|---|
| 0 | Bitmaske der berührten Taste(n): Bit n−1 = Ziffer n (`01` = 1 … `80` = 8) |
| 1 | Nummer der Ziffer (1–8), 0 = keine |
| 2–7 | immer `00` |

`0x2E` meldet die **Berührung**, nicht den Klick: Ein aufgelegter Finger
ohne Druck ergibt schon `08 04`. Beim Rutschen von einer Ziffer zur nächsten
sind kurz zwei Bits gesetzt (4 → 8: `88 04`, dann `80 08`); die Nummer
bleibt bis zum Wechsel auf der vorigen Ziffer. `0x2E` ist entprellt: Ein
kurzes Streifen, das `0x20` als Ziffer 5 meldete, kam in `0x2E` nicht an.

## Status: `0x20` (unentprellt)

| Byte | Bits | Bedeutung |
|---|---|---|
| 0 | | Bitmaske wie `0x2E`, unentprellt |
| 1 | 0–3 | mit Maske: Ziffer; ohne Maske: kleine Stufe 0–15, vermutlich Annäherung (steigt vor einer Berührung über `02`, `05`, `09` bis `0F`) |
| 1 | 4 (`10`) | **mechanischer Schalter** gedrückt |
| 1 | 5, 7 | nie gesehen |
| 1 | 6 (`40`) | Response_Error (LIN 2.x): fehlerhafter Frame an `0x01` empfangen, steht in genau einer Antwort |

- `0x20` wechselt bei liegendem Finger fast mit jeder Antwort zwischen der
  Position (`08 04`, gedrückt `08 14`) und einem Inhalt mit Maske `00`
  (`00 00`, gedrückt `00 10`). Der Schalter steht in beiden.
- Gelegentlich kommt `FF 0F` bzw. `FF 1F` (alle Maskenbits gesetzt), auch
  ohne Berührung, teils minutenlang gehäuft. Ursache unbekannt; vermutlich
  ein Ungültig-Wert.

Beispiele:

| `0x20` | `0x2E` | Bedeutung |
|---|---|---|
| `00 00` | `00 00` | nichts |
| `08 04` | `08 04` | Finger auf Ziffer 4, nicht gedrückt |
| `08 14` | `08 04` | Ziffer 4 gedrückt (Klick) |
| `88 04` | `88 04` | Finger rutscht von 4 nach 8 |
| `00 40` | | Response_Error |

## Sensorwerte: `0x2A`–`0x2D`

Je vier 16-Bit-Werte, **Big Endian** (MSB zuerst).

| ID | Wort 0 | Wort 1 | Wort 2 | Wort 3 |
|---|---|---|---|---|
| `0x2A` | ohne Taste Rauschen (±1), bei Berührung Maske und Nummer (`02 02`, `04 03` …) | Stärke Ziffer 2 | Ziffer 3 | Ziffer 4 |
| `0x2B` | Stärke Ziffer 5 | Ziffer 6 | Ziffer 7 | Ziffer 8 |
| `0x2C` | Rohwert 1? (~520) | ~453 | ~499 | ~580 |
| `0x2D` | ~517 | ~443 | ~483 | ~623 |

- `0x2A`/`0x2B` sind vorzeichenbehaftet, in Ruhe −1 … +3; bei liegendem
  Finger steigt der Wert der Ziffer auf 9–23. Für Ziffer 1 gibt es keinen
  eigenen Wert (Wort 0 von `0x2A` ist dann belegt).
- `0x2C`/`0x2D` reagieren nicht auf Berührung und driften in 10 Minuten um
  1–3; nach dem Einschalten der Beleuchtung lagen sie bis zu 13 niedriger.
  Vermutlich Grundlinien der 8 Sensorflächen, Zuordnung zu den Ziffern
  nicht geprüft.

## Beleuchtung: `0x01`

Wie beim [Bedienteil](AUDI_8W1919616.md#tastenbeleuchtung-id-0x01): ein
Datenbyte, Helligkeit in Prozent, enhanced. Beobachtet: `01` sehr dunkel
(sichtbar im Wechsel mit `00`), `32` sichtbar dunkler als `64`, `64` und
`FF` gleich hell. Das Licht geht beim Annähern nicht von selbst an.

## Abfragen

```python
lin.send_frame(0x01, bytes([100]), ChecksumType.ENHANCED)   # Licht voll
lin.send_header(0x2E, wait=True); time.sleep(0.02)          # berührte Ziffer
lin.send_header(0x20, wait=True); time.sleep(0.02)          # Schalter
```

Header nur nacheinander mit Pause senden (siehe PROTOKOLL.md, „Fremder Slave“).
